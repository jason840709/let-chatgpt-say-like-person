# 子代理誤讀審查、七重 Reviewer Gate 與最終交稿檢查表（第 4.7、25、30 節）

> 節號沿用舊版，位置見 [SKILL.md](../SKILL.md) 的「節號對照」。依入口的任務路由選讀相關章節；檢查層級、委派條件與成品檢查範圍以入口「分級檢查」為準，不因讀到本檔而擴大任務。

# 4.7 子代理逐句尋找合理誤讀

作者讀過全部材料，容易忽略自己省略的前提。依入口第三級處理的完整研究或方法解釋、重要決策與全面稽核，不論在聊天或檔案中交付，可用且允許委派時，請一位未讀作者私下背景的獨立代理逐句找出合理誤讀。沿用目前模型，不另開付費 AI API。無工具、委派不允許或執行中斷時，依本節替代程序由作者逐句檢查。第一、二級短回答、局部改寫及簡單進度不因讀到本檔而啟動獨立審閱。

### 審查輸入與動作

- 給代理讀者的身分、已知與未知，以及實際要交付的文字、圖表和圖說；不要提供作者私下想表達的答案來補洞。
- 若宣稱「未讀後文的首次閱讀」，實際分段提供文字，讀完一段再提供下一段；不要一次交付全文卻聲稱代理沒看過後文。
- 逐句列出：原句、讀者可能理解成什麼、哪個字或缺少的前提容許這個理解、這個理解是否會改變操作或結論。每句都要檢查；輸出可以合併無歧義句子的覆蓋範圍，避免冗長逐句打勾。
- 找的是在指定讀者知識下**合理的另一種讀法**，不是故意無視已解釋的前文、替每個常用詞製造哲學歧義，或要求每句重述整份文件。
- 主代理逐項判斷。若誤讀成立，補上具體對象、操作、比較兩端或範圍，再請同一代理複核有改動的句子；若不成立，保留原因。代理說「通過」不能代替作者的判斷。
- 保存一份精簡審查紀錄：審查文字版本、實際代理、有效歧義及處理。可用既有專案驗收紀錄或工具輸出，不為此建立多層資料夾。交付後新增實質內容，須檢查新增及受影響的文字。

### 必查的易誤讀寫法

1. **範圍量詞**：「只有」與「主要／以……為主」不同。只測一類對象就直說只測一類；「主要」要有其他已測對象的事實基礎。「完整」須交代完整的是公式、資料範圍、工作或證據。
2. **程序壓縮**：「確認研究」「最後一輪」「固定設定」「產生新資料」不能單獨承擔方法說明。交代哪一次工作、誰產生什麼資料、保持哪些設定、重做多少次，以及「一次」指一條資料、一批資料還是一個研究階段。
3. **比較條件省略**：方法在不同公式、區間或資料上的結論，必須在各句帶出條件。不能把甲條件下的方法 A 與乙條件下的方法 B 接著講，讓讀者以為是同條件直接比較。
4. **符號與多義詞**：組合數就寫「幾種方法、幾種模型，共幾種組合」；涉及乘法、卷積等運算才使用對應符號。若「加密」實指增加搜尋點，寫清「在相鄰候選值間再加入候選值」，不要讓讀者猜是在談密碼學或資料處理。
5. **論據層級**：程式採用某規則、作者選擇某規則、實測支持某規則最佳，是三件事。說明方法由來時分開，不能用「程式這樣做」冒充「物理上必須這樣做」。

以上例詞是歧義示例，不是所有領域的禁用詞表。已充分定義、語境清楚時可用既有術語。對重要科學概念，優先補準確的操作與圖例，不以新造簡稱替代說明。

### 誠實回報與成本

若原生子代理不可用、委派不允許或執行中斷，改做作者逐句檢查，交付時簡短說明「已完成作者逐句檢查，未完成獨立審閱」及影響，不因這一項扣住成果。不要偽造收據或保證零誤解。沿用已完成且仍適用的來源與數字查核，歧義審查本身不觸發重跑實驗、重做統計或新增研究。

# 25. Reviewer Gate：依任務選擇的完整檢查

適用範圍由 SKILL.md 決定。第三級做 A、E、F；涉及方法設計才做 B，統計推論才做 C，證據推論或選擇才做 D。有互動成品時，任何層級另做 G 的相關項目。一般短回答與局部改寫依第一、二級檢查即可。純文字不做互動測試，沒有統計推論不硬套 Gate C。這些角色是檢查角度，不要求每關各派一個代理；查核結果用來修改成品，不逐項展示給讀者。

## Gate A：陌生讀者（Comprehension Reviewer）

先依第 4.6.5 節逐段檢查，保存讀到當下缺少的前提；獨立首次讀者限制後文存取，作者自行檢查則核對每個解釋的出現位置，兩者不得混稱。禁止以後文知識判定前段清楚。接著依第 4.7 節完成適用的逐句歧義審查與概念重述。未解釋的操作、只有結論的教訓或需要後文才能理解的因果，任一項存在即退回。

問：

- 開頭能看懂內容要回答什麼，重要答案及其前提能接得起來嗎？
- 每個正式技術縮寫第一次出現有定義嗎？
- 是否出現「第一列、前者、原本那套、上述方法、同一設定」之類的語意縮寫？若有，能否在同一句直接看出真正指涉內容？
- 抽查含數字的關鍵句，在當句及緊鄰前文能辨認對象、單位、必要分母與比較嗎？沒有數字則略過。
- 抽查含代稱與集合名詞的關鍵句，讀者是否不必回頭超過一句就能解碼？依篇幅及風險決定覆蓋，不設定湊數配額。
- 圖表位置指涉能否讓讀者找到正確內容？若位置不夠清楚，再補名稱；不因使用位置詞本身退稿。
- 「設定、條件、流程、參數、方法、結果」若包含多個實質項目，是否在會影響解讀的地方把項目展開？
- 是否有程式欄位直接進正文？

發現任何理解障礙，先重寫相關段落，再進下一關。

## Gate B：方法學 reviewer

問：

- 研究設計能回答研究問題嗎？
- baseline 合理嗎？
- 比較公平嗎？
- 樣本選擇有偏差嗎？
- ground truth 可靠嗎？
- 是否存在重要混雜或替代解釋？
- 測試資料有沒有被用來調參？

## Gate C：統計 reviewer

問：

- 分析單位正確嗎？
- N、遺漏值、重複測量交代了嗎？
- effect size / CI 是否缺失？
- 多重比較是否處理？
- 模型假設與 diagnostics 是否合理？
- 「顯著」是否真的有統計依據？
- 是否有 p-hacking / HARKing 風險？

## Gate D：重要反例與替代解釋

在內部檢查最可能實質改變結論的反例、替代解釋與分析選擇，並為每個候選問題回答：

- 有什麼資料或設計理由支持這項疑慮？
- 它會如何改變結論方向、強度、適用範圍或行動建議？
- 修正分析、縮小主張範圍或補充哪項資訊，能直接處理問題？

**取消固定數量配額。** 依材料與任務決定需要處理的項目。只把真正影響解讀的結果寫入正文，並以第 14A 節決定最短必要說明；其餘查核留在內部。

有確實反例時處理反例；證據支持明確結論時，保留明確結論。

---

## Gate E：Editor

最後問：

- 摘要和正文一致嗎？
- 主結果是否被旁枝統計淹沒？
- 文章是否有自然敘事而非條列堆疊？
- 直接答案可放開頭；理解答案所必需的操作與前提，是否已在當句或緊接說明中交代？版本表是否將尚未解釋的操作壓成口號？
- 結論是否超出證據？
- 文字是否像自然繁中而非英翻中？
- 依第 14B.2a–2c 節檢查：使用者能否讀懂建議和理由？是否省掉必要關係、留下空話，或改變原有的判斷依據、時間與負責動作的人？是否為湊齊格式而追加限制？出現理解缺口或原意變動就重寫，篇幅以說清楚為準。
- 圖表與 PDF 是否真的能讀？

## Gate F：防禦性用詞與結論價值（第三級）

逐項確認：

- 每一處防禦性子句都通過第 14A.3 節的必要性測試。
- 第 14A.4 節觸發的過量情況都已逐句處理。
- 相同限制已合併，必要條件放在讀者容易找到的位置。
- 論證段有實質資訊，全文有清楚的主要發現或建議。
- 決策文件已交代選擇與理由；純改寫保留來源原意。
- 已檢查跨句、同義詞、括號、表格、圖說和頁尾中的重複自保。
- 真正的不確定性與必要風險資訊完整保留，主張強度符合證據。

**任何一項未通過，就退回相關段落改寫並重跑 Gate F。** 標題、摘要、正文或排版文字修改後，再確認一次。適用檢查通過後才交付。

## Gate G：互動成品（有相應功能才檢查）

- 開頭已回答可回答的具體問題，沒有用計畫式進度代替答案。
- HTML 交付前的可見文字，包括實際存在的動態文字、按鈕、圖例和錯誤訊息，已檢查清楚指涉、必要定義與鄰近重複。
- 有曲線或擬合結果時，來源、角色、單位與相關取樣方式可查。估計值依保存結果呈現；只有實際具備真值、門檻及正式判定時才顯示相應比較，不補造缺少的欄位。
- 互動控制只改變它所控制的區域；重要狀態可往返切換，沒有殘留、死按鈕或把單次紀錄誤當成整體結果。
- 版面已檢查圖例裁切、座標軸範圍、按鈕間距、手機版導覽和收合狀態；無法執行的瀏覽器檢查已明確列為限制。
- 交付訊息只報告實際完成的檔案與檢查，不使用虛構的進度、工具輸出或未執行的測試結果。

**適用項目發現問題時，修正相關成品並複核受影響功能。** 不適用的項目略過；無法執行的檢查如實說明範圍與影響，不宣稱通過。所有層級的回報誠信仍由入口核心原則 8 保障。

# 30. 最終交稿 Checklist

這份清單供第三級收尾查漏，依入口與第 25 節選擇適用項目。已檢查且未變動的項目沿用結果；不適用的項目略過，不在成品中填滿「不適用」。

## 30.1 研究問題

- [ ] 第一頁看得出來研究在問什麼。
- [ ] 對話先回答使用者眼前問題，再補方法與限制。
- [ ] 同一視線範圍內沒有重複標題、重複圖例或同義冗言。
- [ ] 主結果真的回答研究問題。

## 30.2 名詞與指標

- [ ] 每個正式技術縮寫第一次出現都有定義。
- [ ] 沒有「第一列、前者、原本那套、上述方法、同一設定」等需要讀者回頭猜的語意縮寫。
- [ ] 代稱與位置指涉在當句及前一句可辨認；不明確時已補內容名稱。
- [ ] 「設定、條件、流程、參數」等集合名詞，在影響結論時已把內含項目展開。
- [ ] 每個核心指標都說明衡量對象、公式、方向與彙整方式。
- [ ] 程式欄位沒有直接冒充自然語言。

## 30.3 數字

- [ ] 每個重要百分比的 n/N 都能找到。
- [ ] 分母是什麼寫清楚。
- [ ] 百分比與百分點沒有混用。
- [ ] 重複測量與分析單位沒有混淆。
- [ ] 平均、median、加權方式交代清楚。

## 30.4 統計

- [ ] N、effect size、不確定性有適當呈現。
- [ ] p 值沒有被當成效果大小。
- [ ] 多重比較有處理或標示探索性。
- [ ] 缺失資料有交代。
- [ ] 模型假設與 diagnostics 在需要時有檢查。

## 30.5 結論

- [ ] 沒有把「比基準差」寫成「程序失敗」。
- [ ] 沒有把相關寫成因果。
- [ ] 沒有把樣本內冠軍寫成泛化冠軍。
- [ ] 沒有把 stress test 結果吞掉正常操作區。
- [ ] 已處理真正影響結論的反例與限制。
- [ ] 結論強度和證據強度一致。
- [ ] 主要發現或判斷清楚，決策任務有選擇及理由。

## 30.6 中文

- [ ] 沒有英翻中語序。
- [ ] 沒有大量被動名詞化。
- [ ] 沒有連接詞模板。
- [ ] 沒有「不是 A 而是 B」成癮。
- [ ] 沒有三段式強迫症。
- [ ] 沒有同義詞亂換。
- [ ] 沒有虛假範圍與意義膨脹。
- [ ] 正式成品沒有客套對話包裝；聊天回答的自然語氣與任務相符，沒有無用的 AI 自述或討好語。

## 30.7 表格與圖

- [ ] 標題可單獨理解。
- [ ] 欄位與單位清楚。
- [ ] n/N 可追溯。
- [ ] 圖軸與誤差棒定義清楚。
- [ ] 圖表沒有視覺誤導。
- [ ] 每條線的研究角色、顏色、線型和圖例一一對應。
- [ ] 顯示取樣、插值或加密繪圖沒有改寫正式評分資料。

## 30.8 文件

- [ ] PDF / DOCX 逐頁檢查；HTML 已檢查閱讀與功能。
- [ ] 沒有截字、亂碼、過小表格或公式溢出。
- [ ] 圖表編號與正文一致。
- [ ] 不同輸出版本中的數字一致。

## 30.9 防禦性用詞與結論價值（鎖定驗收）

- [ ] 每一處防禦性子句都有必要性，並使用最少文字。
- [ ] 所有過量觸發項目都已檢查，重複或可刪的免責已移除。
- [ ] 已清理跨句、跨段、表格、圖說與頁尾的同義重複。
- [ ] 各論證段保留實質資訊，主要結論可被清楚辨認。
- [ ] 真正影響解讀的限制、來源原意及必要風險資訊完整保留。
- [ ] 第三級已完成 Gate F；有互動成品才完成 Gate G 的適用項目，未完成的檢查已如實交代。
