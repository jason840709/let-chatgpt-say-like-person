# 從公開版 2.6.0 升級到 2.8.1

本次比對的起點是 GitHub 主分支與最新 Release 的 **v2.6.0**（提交 `c1c53f2e878bbf7026a2db5f9b564c955fdbff0a`）。2.7.x與2.8.0是中間開發版本，沒有另發公開Release；本頁因此記錄下載者從2.6.0升級會遇到的全部主要差異。

## 寫作與審查行為的差別

| 項目 | 公開版2.6.0 | 2.8.1 |
|---|---|---|
| 讀者依序理解 | 有理解順序與代稱要求，但規則分散 | 集中要求當句就能理解，不能用後文替前文補定義；先說資料構成、模型與指標，再用它們作推論 |
| 主語 | 語境明確時可自然省略，較容易忽略研究動作的行為人 | 行動問句、段首與跨句研究動作寫明誰做；資料、模型等客觀描述用技術主語，同句可自然承接 |
| 原意與來源 | 保留數字、條件、時間、行為人及證據強度 | 保留這些要求，另明確檢查公式的一般參數條件、案例之間的資訊混入，以及引用原話的來源 |
| 常讀內容 | 核心與參考檔分開，但多份文件仍重述原則 | 以六項核心原則為共同入口，兩份示例檔和審稿手冊縮短；七份參考檔仍可按需查閱 |
| 修訂複核 | 已有適用層級與獨立審查 | 更明確寫出一次初審、作者判讀、修訂後局部複核；預設回合數不阻擋必要檢查 |
| 逐句閱讀紀錄 | 有順讀與歧義審閱要求 | 區分一次取得全文的順讀審查，以及每次只提供下一單位的真正逐句供稿；記錄實際覆蓋範圍 |
| 歷史測試 | 如實回報完成範圍 | 明定舊測試繼續綁原版本，新修訂另記，不把目前檔案指紋當成過去受測內容 |

本版以減少無關讀取與重複審查來控制成本。AI遇到真正缺少的細則仍可補讀，使用者指定的逐句供稿方式仍需照做。

## 相同範圍的大小比較

| 範圍 | 2.6.0 bytes | 2.8.1 bytes | 減少 |
|---|---:|---:|---:|
| SKILL.md入口 | 15,335 | 8,329 | 45.7% |
| 入口＋審稿手冊 | 28,820 | 13,060 | 54.7% |
| 四份常讀文件 | 49,320 | 19,367 | 60.7% |

四份常讀文件指 `SKILL.md`、`review-gates.md`、`reader-and-referents.md`、`natural-zh-tw.md`。這裡量測的是相同公開路徑的UTF-8文字量；日常不必全部讀取。它不是token、費用、速度或帳號額度的測量，也不證明品質改善百分比。逐檔數字在 [大小紀錄](v2.8.1-size-comparison.json)。

## 升級方式與相容性

公開啟用名稱、ZIP內頂層資料夾仍是 `let-chatgpt-say-like-person`。下載新版完整ZIP後，用新版資料夾取代舊版，保留 `references/`，不用改原有的啟用指令。

舊第3–4.6、16–18等細則仍有對應位置；原則已集中或合併的部分，以入口「需要時再查」與具名標題為準。若自行維護的提示詞依賴舊原則編號，建議改用規則名稱或檔案路徑。

獨立代理、特定產品或外部API不是安裝必要條件。需要查來源、讀圖或測成品時，仍取決於使用環境提供的工具。

## 這次有哪些測試支持？

測試使用2.7.1與2.8.1初稿做12題一次性對照，後續修訂另做三題入口測試與兩題局部複測；沒有把它描述成2.6.0與最終2.8.1的直接品質比較。兩個對照版本均符合34項指定要求，但還有核對點以外的問題，因此不以通過數字宣稱「全文無誤」。完整說明見 [VALIDATION.md](../VALIDATION.md)。

發布版沿用受測寫作規則，僅保持既有公開名稱並調整公開說明與封裝。下載包不含本機路徑、私人研究紀錄、帳號憑證或整份對話。
